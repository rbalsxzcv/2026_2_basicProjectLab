# AI 반려식물 코치 — 4인 협업용 바이브 코딩 지침

기술개발 명세서 v2를 바탕으로, AI 코딩 도구에 넣을 지침을 **공통 6개 + 페이지 6개**로 나눈 것입니다.
**공통(C1~C6)은 팀원 A 한 명이** 만들고, 끝나면 공통 인터페이스를 동결한 뒤 **페이지(P1~P6)를 팀원 B·C·D가 2개씩 맡아 동시에** 만듭니다.

> 이 README만 한국어이고, AI에 넣는 지침 파일(00_MAIN, C*, P*)은 토큰을 줄이기 위해 영어로 썼습니다. 화면에 보이는 문구와 AI 프롬프트 템플릿 본문은 한국어 그대로입니다.

## 이전 버전에서 바뀐 점

| 항목 | 이전 | 지금 |
| :--- | :--- | :--- |
| 백엔드 | Node.js + Express 서버(AI·날씨 프록시) | **서버 없음. Firebase + AI API 호출만** 사용 |
| AI 호출 | 서버 `/api/ai/*` → AI 제공자 | 브라우저에서 **Firebase AI Logic**(Gemini Developer API)으로 직접 호출. AI 키가 코드에 없고, App Check가 보호 |
| 날씨 | 서버에서 기상청 API(키 필요, 격자 변환) | 브라우저에서 **Open-Meteo**(키 없는 공개 API, 위·경도 그대로 사용) |
| 설치·실행 | `npm install` → `npm start` | 설치 없음. VS Code **Live Server** 또는 `python -m http.server`로 `public/` 열기 |
| 프롬프트 시험 도구 | 명령줄 `npm run try-prompt` | 브라우저 화면 `#/prompt-lab` (P2) |
| 분담 | 묶음 1을 4명이 함께 → 기능 4묶음을 1명씩 | **공통을 1명(A)** → **페이지 6개를 3명(B·C·D)이 2개씩** |
| 시작 작업(`startup.js`) | 기능 묶음이 구역을 나눠 수정 | 공통에서 **뼈대와 미리 연결 완료** → 페이지 담당은 이 파일을 건드리지 않음 |

기획 내용(화면 구성, 데이터 구조, 경험치 규칙, 문구, 완료 기준)은 바뀌지 않았습니다.

## 역할 분담

| 팀원 | 맡는 지침 | 분량 | 특징 | 이런 팀원에게 추천 |
| :--- | :--- | :--- | :--- | :--- |
| **A (공통)** | C1~C6 | 대 | 앱 전체의 뼈대·로그인·식물 등록·메인·AI 연결. 동결 후에는 **통합 담당**(PR 리뷰, 공통 버그 수정, 계약 변경 반영, 배포) | Git·구조를 가장 먼저 익힐 사람 |
| **B** | P1 캘린더 + P2 프롬프트 실험실 | 중상 + 소 | 달력 UI + 2단계 AI 대화 흐름, 프롬프트 품질 관리 | 화면 구성과 AI 출력 다듬기를 좋아하는 사람 |
| **C** | P3 체크리스트 + P4 알림 | 중상 + 소 | 데이터 규칙이 가장 많음(트랜잭션, 일정 연기, 경험치) + 알림함 | 로직을 꼼꼼히 보는 사람 |
| **D** | P5 환경 분석 + P6 월간 리포트 | 중 + 중 | 카메라 API + 통계 집계 | 브라우저 API·데이터 집계에 관심 있는 사람 |

* B·C·D는 서로 관련 있는 페이지끼리 묶었습니다(P1↔P2는 진단 프롬프트, P3↔P4는 체크리스트 알림, P5↔P6는 환경 기록·통계).
* 공통 단계 동안 B·C·D는 A의 PR을 **리뷰하며 공통 함수 형식을 익히고**, 명세서·화면 스케치·프롬프트 샘플 입력을 준비합니다.

## 각 페이지를 혼자 테스트할 수 있는 이유

각 페이지는 **메인 화면 + 공통 인터페이스만 있으면** 다른 페이지 없이 동작하도록 설계했습니다.

1. **뼈대(stub):** 여러 페이지가 서로 부르는 함수는 C5에서 최종 이름·형식 그대로 단순하게 동작하는 뼈대로 먼저 만듭니다. 각 담당자는 자기 뼈대 파일의 **안쪽만** 완성본으로 바꿉니다.

   | 뼈대 파일 | 누가 완성 | 완성 전 동작 | 부르는 곳 |
   | :--- | :--- | :--- | :--- |
   | `ui/diagnosis-flow.js` | B (P1) | 사진만 기록 | 캘린더, 체크리스트 |
   | `services/checklists.js` | C (P3) | 기본 루틴으로 체크리스트 생성, 완료는 안 됨 | 메인, 시작 작업, 알림 |
   | `services/notifications.js` | C (P4) | 아무것도 안 함(뱃지 0) | 시작 작업 |
   | `services/reports.js` | D (P6) | 빈 결과 | 시작 작업, 알림 |

2. **AI·날씨 mock:** 기본값 `mock` 모드에서는 실제 AI 없이 그럴듯한 가짜 응답이 나옵니다. `#/dev`에서 각자 브라우저에만 적용되는 mock/real 전환 스위치가 있어서 파일을 고치지 않아도 됩니다.
3. **`#/dev` 테스트 버튼:** 공통 버튼(물주기 예정일 바꾸기, 오늘 체크리스트 지우기 등)과 페이지별 구역(`[P1]`~`[P6]`)이 있습니다.
   * 예) P3의 [사진으로 확인] 버튼은 P1이 머지되기 전에는 사진만 기록됨 → 정상
   * 예) P6의 리포트는 체크리스트 완료 기능 대신 [지난달 샘플 기록 만들기]로 시험
   * 예) P4의 리포트 알림은 [테스트 알림 만들기]로 시험

## 진행 순서

### 0. 시작 전에 (한 번만, A가 진행하고 모두 초대)
1. 저장소를 만들고 `docs/SPEC.md`에 명세서 v2를, `docs/vibe/`에 이 폴더를 그대로 넣습니다.
2. [Firebase 콘솔](https://console.firebase.google.com)에서 프로젝트를 **하나** 만들고 4명 모두 초대합니다.
   * Authentication → 이메일/비밀번호 사용 설정
   * Firestore Database 만들기 (위치: `asia-northeast3`(서울) 권장)
   * **AI Services → AI Logic → 시작하기 → Gemini Developer API** 선택 (무료 Spark 요금제에서 사용 가능)
   * 설정 과정에서 **App Check**가 함께 켜집니다. reCAPTCHA 사이트 키를 만들어 두고, `localhost` 테스트용 **디버그 토큰**은 각자 브라우저 콘솔에 찍힌 값을 App Check → 디버그 토큰 관리에 등록합니다(C1에서 안내).
   * 프로젝트 설정 → 웹 앱 추가 → `firebaseConfig` 값 복사 (C1에서 사용)
3. 4명 모두 **VS Code + Live Server 확장**(또는 Python)을 준비합니다. Node.js 설치는 필요 없습니다.
   * 휴대폰 카메라 테스트·시연처럼 HTTPS가 필요할 때만 Firebase Hosting으로 배포합니다(Firebase CLI 필요, A가 담당).

> Cloud Storage는 종량제(Blaze) 요금제가 있어야 써서 기본 설계에서 뺐습니다. 사진은 압축해서 Firestore에 저장합니다.
> 이미지 생성(데포르메 캐릭터) 모델이 무료 요금제에서 안 되면 캐릭터만 mock SVG로 두면 됩니다(C2에서 AI가 먼저 물어봄).

### 1단계 — 공통 (A 혼자)

| 순서 | 지침 | 비고 |
| :--- | :--- | :--- |
| ① | C1 셸 | |
| ② | C2 AI·날씨 | mock 먼저, 콘솔 설정이 끝났으면 real까지 |
| ③ | C3 인증 | C2와 순서를 바꿔도 됨 |
| ④ | C4 식물 등록 | |
| ⑤ | C5 공유 서비스·뼈대 | 함수 형식을 B·C·D가 PR에서 꼭 같이 확인 |
| ⑥ | C6 메인 게임 | 마지막에 **공통 통합 확인**(가입 → 식물 등록 → 메인) |

지침 하나가 끝날 때마다 PR → (B·C·D 중 1명 이상) 리뷰 → main에 머지합니다. C6이 머지되면 `docs/PROGRESS.md`에 **"공통 완료·동결"** 을 적고 2단계로 넘어갑니다.

### 2단계 — 페이지 (B·C·D 동시에)
1. 각자 main에서 자기 브랜치를 만듭니다: `feat/p1-calendar`, `feat/p3-checklist`, `feat/p5-environment` 등 (같은 사람의 두 페이지는 한 브랜치로 해도 됩니다).
2. **Firebase는 같은 프로젝트를 쓰되, 각자 테스트용 계정을 따로** 만드세요. 보안 규칙상 계정별로 데이터가 분리돼서 서로 테스트를 망가뜨리지 않습니다.
3. 기본은 `mock` 모드입니다. 실제 AI는 `#/dev`의 스위치로 각자 켜 봅니다(무료 사용량과 하루 호출 한도가 있으니 필요할 때만).
4. 끝나면 PR → **다른 담당자 1명 이상 리뷰** → main에 머지. 리뷰할 때는 공통 파일을 건드리지 않았는지(`git diff main --stat`)를 꼭 확인합니다. 허용된 파일은 `00_MAIN.md` 9.3절 표에 있습니다.
5. 공통 파일에 버그가 있으면 직접 고치지 말고 A에게 알립니다. A가 main에서 고치면 각자 `git merge main`으로 받아 옵니다.

### 3단계 — 통합 확인 (4명 함께)
모든 페이지를 머지한 뒤 한 계정으로 처음부터 끝까지 진행해 봅니다.
1. 회원가입 → 첫 식물 등록(사진 → 캐릭터) → 메인 화면
2. AI 환경 분석(조도 측정 → 점수 → 조언)
3. 성장 캘린더 사진 진단 → 관찰 필요(ALERT, 돋보기) 확인
4. 체크리스트: 물주기 Safe-Lock — [아직 축축해요] → 2일 연기 / [말라 있어요] → +20 EXP, 레벨업
5. 체크리스트에서 [사진으로 확인] → 이제 질문·처방까지 진행되는지 (P1 + P3 연결)
6. 로그인 → 체크리스트 알림 → 알림 눌러 체크리스트로 이동 (P3 + P4 연결)
7. `#/dev`에서 지난달 샘플 기록 → 다시 로그인 → 리포트 알림 → 리포트 열람 (P4 + P6 연결)
8. `#/dev`에서 AI·날씨를 real로 바꿔 2~7을 한 번 더

## AI에게 붙여 넣을 문장

**새로 시작할 때** (파일 이름만 자기 지침으로 바꾸세요)
```text
docs/vibe/00_MAIN.md 와 docs/vibe/pages/P3_checklist.md 를 읽고 이 지침의 작업을 진행해 줘.
시작하기 전에 docs/PROGRESS.md 와 "Prerequisites"에 적힌 기존 파일들을 먼저 열어서 실제 함수 이름을 확인하고,
만들 파일 목록과 순서를 알려 준 다음 시작해. 지침의 수정 허용 파일 목록 밖의 파일은 고치기 전에 나한테 물어봐.
설명과 주석은 한국어로 해 줘.
```

**대화가 길어져 이어서 할 때**
```text
docs/vibe/00_MAIN.md 와 docs/vibe/pages/P3_checklist.md 를 읽어 줘. 이 작업을 이어서 하는 중이야.
docs/PROGRESS.md 와 지금까지 만든 파일을 확인하고, "Done when" 항목 중 아직 안 된 것부터 진행해 줘.
```

## 공통 인터페이스를 바꾸고 싶을 때
1. 직접 고치지 말고 팀 채널에 "계약 변경 제안"으로 올립니다(무엇을, 왜, 영향받는 페이지).
2. 4명이 합의하면 A가 `00_MAIN.md`를 먼저 고치는 PR → 공통 파일 수정 PR 순서로 main에 머지합니다.
3. 각 브랜치는 main을 받아 옵니다(`git merge main`).

명세서의 "회의 후 확인 필요 사항"(쓰다듬기 경험치, 아이디 형식 등)이 결정되면 `00_MAIN.md` 5.6·5.9절의 값만 바꾸면 됩니다.
